# DS Status (状态页订阅)

![logo](logo.png)

订阅 DeepSeek 的状态页和邮箱通知，状态一变就推一张卡片过去。

- 版本：0.2.0
- 作者：Fangnai-byte
- 仓库：https://github.com/Fangnai-byte/astrbot_plugin_ds_status

## 它做什么

两个来源，可以只开一个，也可以都开。

- **状态页 RSS**：默认 `https://status.deepseek.com/feed.rss`，能换成任意 RSS 2.0 或 Atom 地址。
- **邮箱通知**：走 IMAP 收信。DeepSeek 的邮件比状态页早几分钟，有些内容状态页上根本没有，比如计费调整预告、搜索服务收费提醒。

发现有新状态就推给所有订阅过的会话，默认每 600 秒查一次。首次加载只记录不推送，装好不会刷一屏旧消息。

推送形式三选一：图片卡片、合并转发、纯文本。渲染失败会自动退到文本，不会憋着不发。

## 为什么要按「事件 + 状态」去重

一次故障，两边的表现完全不同：

- 状态页上只有一条 item，内容是原地改写的，guid 一直不变
- 邮箱里连发十几封，每封 Message-ID 都不一样

只按常规 id 去重都会出问题。认 RSS 的 guid，后续「监控中 → 已恢复」全被当成已推送吞掉；认邮件的 Message-ID，两小时刷十几条。

所以去重键是 `事件编号#状态`，例如：

```
incident:7202016104287#monitoring
incident:7202016104287#resolved
```

同一事件同一状态只推一次。RSS 和邮件也会算出同一个键，两边同时有这条时只发一条。

## 安装

把整个 `astrbot_plugin_ds_status` 文件夹放进 `data/plugins/`，在面板里重载插件。首次运行会在 `data/plugin_data/astrbot_plugin_ds_status/` 下建状态文件。

想用邮箱源，先去 QQ 邮箱的 `设置 → 账户 → POP3/IMAP 服务` 生成授权码。授权码不是登录密码，填进 `mail_auth_code`，再把 `mail_enabled` 打开。

## 命令

| 命令 | 作用 | 权限 |
| --- | --- | --- |
| `/ds订阅` | 让当前会话开始接收推送 | 管理类 |
| `/ds退订` | 取消当前会话的订阅 | 管理类 |
| `/ds订阅列表` | 查看已订阅的会话 | 管理类 |
| `/ds检查` | 立即轮询一次，有新条目就推送 | 管理类 |
| `/ds测试` | 往当前会话发一条测试推送 | 管理类 |
| `/ds状态` | 立即拉取并查看最新 3 条（只读，不影响推送记录） | 所有人 |
| `/ds帮助` | 查看订阅源、间隔、上次检查时间、最近错误 | 所有人 |

「管理类」默认仅管理员可用，配置里把 `admin_only` 关掉，白名单用户也能用。

`allow_user_ids` 是额外一层白名单。留空表示所有人可敲命令，填了就只认列表里的号。两层是「先过白名单，管理类再过 admin_only」，都通过才执行。

## 配置

**订阅源**

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | true | 关掉就不轮询，只能手动敲命令 |
| `rss_url` | DeepSeek 状态页 | RSS 2.0 与 Atom 都支持 |
| `poll_interval_sec` | 600 | 轮询间隔，建议不低于 300 秒 |
| `timeout_sec` | 20 | 单次请求超时 |
| `proxy` | 空 | 走代理时填 `http://127.0.0.1:7890` 这类地址 |
| `user_agent` | Mozilla/5.0 (AstrBot DsStatus) | 被源站拒绝时可换一个 |

**邮箱**

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `mail_enabled` | false | 打开后才收邮件 |
| `mail_imap_host` | imap.qq.com | IMAP 服务器 |
| `mail_imap_port` | 993 | 端口，SSL |
| `mail_user` | 空 | 完整邮箱地址 |
| `mail_auth_code` | 空 | 授权码，不是登录密码 |
| `mail_folder` | INBOX | 监听的文件夹 |
| `mail_from_filter` | deepseek | 只收这个发件人的信，留空表示不过滤 |
| `mail_lookback_days` | 3 | 只回看最近几天的邮件 |
| `mail_max_per_check` | 8 | 每次最多解析几封 |
| `mail_timeout_sec` | 20 | 连接超时。QQ 限流时不回包，没超时会一直挂着 |

**推送**

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `push_as_image` | false | 渲染成图片卡片 |
| `use_forward` | true | 用合并转发，`push_as_image` 优先 |
| `forward_name` | DS 状态订阅 | 合并转发里显示的名字 |
| `initial_sync` | false | 首次运行是否推送已有条目 |
| `push_max_entries` | 3 | 单次最多推几条 |
| `filter_keywords` | 空 | 只推包含这些词的条目，留空表示全部 |
| `ignore_keywords` | 空 | 跳过包含这些词的条目 |
| `max_content_chars` | 300 | 正文截断长度 |
| `include_link` | true | 推送里带不带原始链接 |

## 卡片长什么样

页眉是 DeepSeek 的 logo 加「状态更新」，右上角是这次推送的时间。下面每条一个状态药丸：监控中橙色、已恢复绿色、调查中红色、维护紫色。再往下是时间、来源、正文和原文链接。正文超过 600 字会截断。

渲染用 Pillow 直接画，不需要浏览器，也不把内容发到任何第三方。

## 数据存放

订阅关系、已读记录、上次检查时间和最近错误都在 `data/plugin_data/astrbot_plugin_ds_status/state.json`。

写入是「先写临时文件再替换」的原子方式，进程被强杀也不会写坏。删掉这个文件等于重置订阅，已读记录最多留 300 条。

## 排错

1. `/ds帮助` 看上次检查时间和最近一次错误
2. `/ds状态` 手动拉一次，确认源本身取不取得到
3. 还不行就看日志里 `[astrbot_plugin_ds_status]` 开头的行

常见情况：

- **403**：源站按区域或 IP 拦截，先配 `proxy`；也可能是 UA 被拒，换一个 `user_agent`
- **超时或连接被重置**：网络或代理问题，调大 `timeout_sec`
- **解析到 0 条**：返回的不是 RSS，多半被拦截页替换了正文
- **邮箱登录失败**：检查是不是把登录密码填进了 `mail_auth_code`，以及邮箱有没有开 IMAP
- **邮箱一直超时**：QQ 对并发连接有限制，插件用的是常驻连接，不会每轮重登；真要重来就重载插件
- **推不到**：有些平台不支持机器人主动发消息，这种会话订阅了也推不过去，日志里会有「找不到平台会话」
